# Dense Reid with angles: selected-set audit

This audit covers only the deterministic, response-independent selected 100 trajectories used by the dense-Reid study. It does not make an assertion about the remaining 1,000 raw trajectories.

`data/reid_with_angles_1000_frames.pt` contains 100 trajectories of 1,000 frames; `data/reid_with_angles_first101.pt` contains their exact frame-0 through frame-100 prefixes. The conversion preserved raw `x`, `edge_index`, and `edge_attr` tensors bit-for-bit, replaced `network.Box` with pickle-portable `graph_utils.box.Box`, and added `source_name='reid_dense'`, `source_sim_id`, `source_chunk`, and `source_frame_index`. It does not invent time, temperature, or a physical timestep.

The source registry has 1,100 unique `sim_id` values and paths to the complete `chunk_0.pt` through `chunk_1099.pt` inventory, in shuffled registry order. Each selected raw chunk is one trajectory with exactly 1,000 frames; it is not a multi-trajectory batch. The selected list uses `random.Random(123).shuffle(sim_id)` and the first 100 distinct exact initial geometry/topology/stiffness identities. It selected no duplicates. The complete mapping, raw-chunk hashes, output hashes, boxes, node and edge counts are in [the conversion manifest](../../../../data/reid_with_angles_1000_frames.manifest.json).

Every one of the 100,000 selected raw frames passed these checks: finite `x` and `edge_attr`; `x` float32 shape `(N, 2)`; `edge_index` int64 shape `(2, E)`; `edge_attr` float32 shape `(E, 4)`; `E` agreement between edge tensors; in-range indices; finite, nondegenerate per-frame boxes; and invariant directed `edge_index` within each trajectory. The graph sizes vary (the selected endpoints include 148 and 200 nodes), so trajectories must remain independently grouped.

The four stored edge columns are `[minimum-image x_source-x_target, minimum-image y_source-y_target, minimum-image length, stiffness]`. The first three were verified from each frame's positions and current box to an absolute tolerance of `2e-6`; stiffness (column 3) is exactly invariant over every trajectory. The signed vectors encode edge orientation. There is no explicit angle list or angular-stiffness field. The directory name alone does not establish whether angular interaction parameters were used in simulation, whether they varied between networks, or whether they can be recovered from these exported features.

All 10,000 adjacent prefix frame pairs changed. For the first 101 frames, absolute coordinate increments have median `2.25544e-4`, 1st/99th percentiles `3.57628e-6`/`1.62840e-3`, and maximum `2.53296e-3`. The median float32 coordinate spacing is `2.38419e-7` (99th percentile `4.76837e-7`), so the median step is 946 spacings and even the conservative 1st-step/99th-spacing comparison is 7.5. The zero minimum is a per-coordinate component after float32 rounding, not a stationary trajectory.

A descriptive per-node/per-coordinate OLS fit of position against frame index over frames 0–100 leaves residual SSE/centered SSE between `1.24244e-6` and `5.85795e-4` across trajectories (median `1.19072e-4`, mean `1.34986e-4`). This establishes observable early-frame deviation from an exactly linear path, while not establishing a physical sampling interval or serving as a rollout baseline.

Neither legacy file shares an exact selected network topology: topology-hash intersections are 0/100 with `data/reid_200_frames.pt` and 0/100 with `data/real_reid_200_frames.pt`. Exact initial geometry/topology/edge-feature intersections are likewise zero. Some node counts overlap, which is not network identity.
