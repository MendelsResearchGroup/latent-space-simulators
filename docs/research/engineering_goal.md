# Gradient-guided network engineering

Optimize an original network using derivatives through a frozen learned model, so the resulting network has the desired physical response, including negative p-ratio. Editable parameters may be spring stiffnesses and/or initial node positions. Keep their physical and normalized graph features consistent. Prefer the AE alone if its representation supplies reliable intervention directions; add the learned propagator when future-response prediction is needed. An AE's reconstruction accuracy does not establish that its gradients predict the effect of network edits.

The optimization path is original network → frozen ML model → downstream differentiable design objective → gradient with respect to network parameters → updated network. The AE and any propagator remain trained on positions, trajectories, and graph structure, without p-ratio supervision or response-based checkpoint selection. A historical response-calibrated latent readout must be identified as such; it is not a position-based autonomous prediction.

Freeze the objective, model, constraints, budget, and final-selection rule before the search. Use ML alone for every optimization decision. Save final graphs and their hashes before running LAMMPS. Final physical verification must never guide proposals, acceptance, stopping, restarts, initialization, or winner selection. Start from original networks rather than designs already selected with simulator feedback. Report all predeclared final designs and failures. Numerical reruns of the same frozen design may check simulation convergence, but cannot change the design.

Success means reliable final physical response across held-out networks and model seeds, with source-wise valid/total counts, target-attainment rates, predicted-versus-measured responses, and predeclared controls. Good reconstruction p-ratio R² is useful evidence but not a guarantee of engineering success. A simulator-guided success does not satisfy this goal.

The earlier `engineering_endpoint_v1` experiment already optimized a frozen AE plus downstream ridge readout without simulation feedback: 150 Adam steps, learning rate 0.02, and a ±0.25 log-stiffness bound. Final verification found decreases for 3/3 Reid and 1/3 low-T dePablo networks, with 6/6 valid final designs and none negative. This one-model-seed validation result is the existing ML-only baseline and does not need an identical rerun. Exact recipes and results are recorded in the [engineering log](../../notebooks/latent_space/network_engineering_log.md).

The Reid53 negative-response animation comes from a later simulator-guided search. It demonstrates a physical engineered response, but does not meet this ML-only engineering goal.

For mixed-temperature engineering, compare position-only and joint position/stiffness edits. Measure thermal p-ratio from linear fits across the saved physical trajectory: fit axial and transverse boundary strains separately against frame index with an intercept, then take minus the transverse/axial slope ratio for x-driven compression. Freeze the frame set and estimator before evaluation; report valid frame/trajectory counts and thermal-seed uncertainty separately from model seeds. An athermal endpoint replay cannot verify a thermal design; preserve the actual thermal simulation protocol or label a separately declared new protocol explicitly.
